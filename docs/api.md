# API

> Status: **design**. All paths are under `/api/v1` on the API process (`127.0.0.1:8200`). The signer
> has its own small API on `127.0.0.1:8201` (§6). The OpenAPI schema generated by FastAPI is the
> source for the web app's TypeScript types.

## 1. Conventions

- JSON in and out. Amounts are **decimal strings in base units** (`"120000000"` for 120 tUSD).
- Addresses are EIP-55 checksummed on output and accepted in any case on input.
- IDs are prefixed ULIDs: `man_`, `ses_`, `prp_`, `dec_`, `apr_`, `sig_`, `run_`, `eps_`, `abk_`.
- Colon verbs (`/approvals/{id}:approve`) are actions on a resource.
- Every POST that creates something accepts an **`Idempotency-Key`** header. A repeat with the same
  key and body returns the original decision (for proposals, without re-issuing the decision token);
  the same key with a different body returns `409`.
- Timestamps are RFC 3339 UTC.
- Every response carries `X-Request-ID`; every trace span carries the same id.

### 1.1 Errors

```json
{"error": "mandate_expired", "detail": "Mandate man_01J9… expired at 2026-10-02T10:00:00Z", "request_id": "req_01J9…"}
```

| HTTP | `error` | When |
|---|---|---|
| 400 | `invalid_request` | Schema validation failed |
| 400 | `unsupported_chain` | Chain id outside `{31337, 84532, 11155111}` |
| 403 | `local_only` | A local-only endpoint called from a non-loopback address |
| 404 | `not_found` | Unknown id |
| 409 | `idempotency_conflict` | Same `Idempotency-Key`, different body |
| 409 | `approval_resolved` | Approving or denying an approval that is no longer pending |
| 422 | `mandate_extraction_failed` | The extractor failed twice (one repair allowed) |
| 422 | `policy_invalid` | Policy validation failed; `detail` lists the problems |
| 428 | `dry_run_required` | `PUT /policy` before a dry-run of that exact file hash |
| 503 | `signer_unavailable` | Signer not configured or not reachable |
| 503 | `rate_limited` | Provider quota exhausted; `Retry-After` header set |

| GET | `/mandates/{id}` | | `Mandate` with `body_sha256` |
| POST | `/sessions` | `{mandate_id}` | `Session` |
| GET | `/sessions/{id}` | | `Session` with spent vs caps per asset |
| POST | `/proposals` | `{session_id, kind, payload, origin?}` | `Decision` |
| GET | `/proposals/{id}` | | Full record: proposal, action, effects, findings, all decisions |
| GET | `/decisions` | `?verdict=&since=&session_id=&limit=` | Page of `DecisionSummary` |
| GET | `/approvals` | `?state=pending` | Page of `Approval` |
| POST | `/approvals/{id}:approve` | `{note?}` | New `Decision` (`decided_by = human`, with token) |
| POST | `/approvals/{id}:deny` | `{note?}` | New `Decision` (`decided_by = human`, block) |
| POST | `/sign` | `{decision_token, proposal_id}` | `{tx_hash}` or `{signature}` for typed data; `503 signer_unavailable` unless the signer is configured |
| GET | `/policy` | | `{yaml, sha256, loaded_at}` |
| POST | `/policy:validate` | `{yaml}` | `{valid, errors[]}` |
| POST | `/policy:dry-run` | `{yaml}` | `{sha256, changed[], counts}` |
| PUT | `/policy` | `{yaml, sha256}` | New policy version (**local only**; requires a prior dry-run) |
| GET | `/address-book` | `?chain_id=` | Entries with `provenance` and `verified` |
| POST | `/address-book` | `{label, address, chain_id}` | Entry (`provenance = user`, `verified = true`) |
| PATCH | `/address-book/{id}` | `{label?, verified?}` | Entry (**local only**) |
| DELETE | `/address-book/{id}` | | `204` (**local only**) |
| GET | `/audit:verify` | | `{ok, rows_checked, first_bad_row?}` |

`kind` is one of `tx`, `typed_data`, `7702_auth`, `x402_payment`. `origin` is `agent`, `mcp` or `api`
(defaults to `api`; the MCP server sets `mcp`).

Entries created through `POST /address-book` from the web app or CLI are the user's. The agent's
`address_book.add` tool writes through an internal path that always sets `provenance = agent`,
`verified = false`; there is no way to set `verified` from the agent or MCP.

## 5. Decision token

```
token   = "wdt1." + b64url(payload_json) + "." + b64url(HMAC_SHA256(secret, payload_json))
payload = {"decision_id": "dec_…", "proposal_sha256": "…", "chain_id": 31337,
           "expires_at": "2026-10-02T10:02:00Z", "nonce": "<128-bit random, hex>"}
```

- `payload_json` is canonical JSON (sorted keys, no whitespace).
- `proposal_sha256` is the SHA-256 of the canonical proposal payload.
- The secret lives in `data/secrets/decision_token.key`, readable by the API and signer processes
  only. The agent process never has it, and the agent's tools never return the token.
- Lifetime: `defaults.token_ttl_s` in the policy (120 s).
- The signer refuses a token that is reused, expired, has a bad MAC, or does not match the proposal.

## 6. Signer API (`127.0.0.1:8201`)

| Method | Path | Body | Returns |
|---|---|---|---|
| POST | `/sign` | `{decision_token, proposal}` | `{tx_hash}` or `{signature}` |
| GET | `/signatures/{decision_id}` | | `{tx_hash, broadcast_at, receipt_status}` |
| GET | `/health` | | `{status, chain_ids, address}` |

Only the API process calls the signer. Checks are listed in [architecture.md §5](architecture.md#5-signer).

## 7. MCP tools (stdio)

| Tool | Input | Output |
|---|---|---|
| `warden_propose_transaction` | `{kind, payload}` | Decision summary (verdict, reasons, codes, `proposal_id`) |
| `warden_request_signature` | `{proposal_id}` | `{tx_hash}` or `{signature}` if the decision is `allow` and the signer is configured; error otherwise |
| `warden_get_decision` | `{proposal_id}` | Latest decision summary (useful after an escalation resolves) |
| `warden_simulate` | `{kind, payload}` | Action + effects, **read-only**, no decision recorded |
| `warden_check_address` | `{address}` | Book match, lookalike matches, first-seen, dust-origin |

**Deliberately absent:** mandate creation, approve/deny, policy edits, address-book writes. The
session id is set by the user in the MCP server's configuration (`WARDEN_MCP_SESSION_ID`), never by
the caller. See [ADR-0010](decisions/0010-mcp-surface.md).
